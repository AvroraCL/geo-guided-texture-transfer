基于几何约束的多视图二维设计向复杂三维模型表面的高保真纹理转译技术

问题定义与方案设计

AvroraCL

独立研究 ｜ 2026 年 10 月 ｜ 草案 v0.5

摘 要

在游戏外观模改的实际生产中，多视图二维设计稿（正交视图）向三维模型表面贴图的转换，至今仍高度依赖人工。图像生成模型已能产出高质量的设计参考与素材，大语言模型已能将模糊的自然语言需求转译为结构化设计意图，但二者均无法完成从外观分布到UV 空间对应这一环节，即参考图上"长这样"的图案究竟对应模型表面哪一位置、跨过 UV 接缝后应如何接续。

本文提出，该环节构成一个独立且当前未被充分解决的中间层问题。其难点不在投影——投影已有成熟工具——而在延续：多视图天然存在信息缺口，背面、凹陷与自遮挡区域缺乏设计信息，图案必须被合理推演填充。本文结合游戏资产生产的六条硬约束，给出该中间层的输入输出契约、三个子问题的分解、三条候选技术路线及其取舍，并设计相应的验证方案。本文不提出新的生成模型，亦不声称已有实现。

关键词：纹理转译；UV 空间；接缝连续性；多视图设计稿；游戏资产生产；中间层

写给谁看

本文面向熟悉 PBR 流程、但不熟悉图形算法与人工智能的美术从业者。UV、接缝、通道这些你们比我熟，本文不解释；反过来，凡涉及算法与模型的部分，本文一律先给类比，再给术语，并尽量配图。

若只关心"哪些能做、哪些不能做、我该怎么安排手上的活"，可直接跳读第 4 章与第 7 章。

1 问题的提出

1.1 实践背景：一条已经半自动化的流水线

当前一套成熟的游戏外观模改流程大致如下 已核对（据作者自身实践）：

  1. 在 Blender 中整理与修复模型，并渲染若干正交视图作为绘制底稿；
  2. 在 Photoshop 等二维软件中依据正交视图绘制设计稿与素材；
  3. 在 Substance Painter 中于三维空间直接绘制，产出符合 PBR 规范的多通道贴图；
  4. 导出并导入游戏，验证效果后迭代修正。

其中已引入人工智能的环节包括抠图、素材生成与参考图生成。图像生成模型配合有经验的设计师，已能产出可用的设计参考 已核对。

1.2 断层所在：外观分布不等于空间对应

有一个容易混淆之处需要先行澄清。视觉模型对参考图所进行的处理，更准确的表述是条件注入，而非"理解三维结构"：结构控制、风格控制与参考图注入等机制所对齐的是外观分布，即"这张图应当长成什么样"；它们并不建立空间对应，即"这一纹样对应模型表面哪一具体位置、跨过接缝后接到何处"。

而中间层所需要的恰恰是后者。这解释了为何单纯提升生成模型的能力无法自动补齐该环节：它不是分辨率问题，也不是语义理解问题，而是空间结构的错配。

核心论断

UV 空间与图像空间的拓扑结构并不一致：UV 图上紧邻的两块，在三维模型上可能相隔很远；三维模型上连续的一片，在 UV 图上可能分属互不相连的岛屿。因此，视觉信息必须被在两个拓扑结构不同的空间之间搬运，而不能简单地投影或复制。

理解上述论断，还有一个前置问题需要先讲清楚：计算机里有两种完全不同的活，一种叫"算"，一种叫"猜"。这是全文最需要区分的一件事，后面所有的分工判断都由它决定。

1.4 研究问题

  • RQ1（对应）：能否在既定 UV 拓扑下，建立设计稿像素与 UV 位置之间稳定、可计算的对应关系？

本文不提出新的生成模型，亦不声称改进了任何现有算法。所调用的视觉生成模型、几何处理与渲染工具均为外部既有组件。本文的工作限于以下四项：

  1. 将该工程断层界定为一个可研究的问题，并给出其形式化描述；
  2. 给出该问题的硬约束清单与输入输出契约；
  3. 梳理设计空间，列出候选路线并分析其取舍；
  4. 设计尚未执行的验证方案。

2 相关工作

本节不综述扩散模型原理，只讨论既有工作各自解决了中间层的哪一部分。在此之前，先解释两个会反复出现的概念。

2.1 两个需要先讲清的概念

沿表面走的距离

两点之间怎么算远近？平时量的是直线——拿尺子一拉，穿过空气。但在物体表面上，"近不近"要看沿着表面走多久。拿一只碗来说，碗口对边的两点，直线一跨就到；可要是只允许贴着碗面走，就得绕下碗底再爬上来，远出好几倍。

后文统一称它为测地距离。为什么非要在意它？因为判断"谁跟谁真的挨着"只能靠它——直线距离会骗人，穿过空气的那种近不算近。

模型拿到的，和它不知道的

第二个概念解释生成模型为什么需要额外帮助。模型拿到的是一张平面图，对它而言只是一堆格子上的数值；它并不知道这些格子对应模型表面的哪一块、朝向哪边。好比有人递给你一张印好的贴纸，却没告诉你该往哪个面贴。

近年的方法（[4]）做的正是补上这段缺失的对应关系：一边生成贴图，一边告知模型"你正在画的这一块，是模型的哪个位置、朝哪个方向"。后文称之为表面感知的位置信息。第 3.5 节讨论的接缝权重，本质上也属于这一类信息。

2.2 从多视角图像到表面纹理

Im2SurfTex [2] 走的是最直接的一条路：先让二维图像模型绕着物体生成一组多视角图像，再把这些图像聚合到物体的纹理空间。

关键在于"聚合"这一步。早期做法是把每张视图按相机参数反投影到表面，重叠处直接取平均，这样会在接缝与遮挡边界留下明显瑕疵。Im2SurfTex 的改进是训练一个神经模块来做聚合，并给每个像素编码其对应的三维位置、法向，以及面片内的测地距离——也就是 2.1 节所讲的"沿表面走的距离"。

这条路线的根本限制在于它依赖多视角图像本身。图像模型没有生成、或生成质量不佳的视角，聚合结果便无从谈起；多视角之间天然存在的遮挡与视角不一致，也始终是它的负担。

2.3 直接在 UV 空间生成

DirectUV [4] 干脆绕开三维空间，直接在 UV 图上生成纹理。

但直接在 UV 空间工作会碰到一个麻烦：UV 图上的坐标只是格子位置，并不等于模型表面的位置。UV 图上挨着的两个格子，在模型上可能分属相隔很远的两块；模型上连成一片的区域，在 UV 图上又可能被切成若干互不相连的岛。

DirectUV 的解法是给位置编码加入表面信息，让注意力绑定到表面几何而非 UV 格子。其摘要中有一句值得原样引用：这种错配"限制了跨接缝与不连通 UV 岛之间的一致性"。这句话正是本文 1.2 节所讨论问题的正式表述。

2.4 几何层面的精确对齐

与前述两条生成路线不同，Robust Curve Embedding [3] 处理的不是整张贴图，而是曲线——设计稿里的线条、轮廓与纹样边界。

它的做法是把每条边表示为代理网格上的测地路径，并在 UV 接缝处精确切分，从而精确复现图块边界。该工作明确以纹理迁移为应用场景，且专门处理"脏"网格：面片混乱、自相交、拼接不一致的网格，也就是游戏模型的常见状态。

其结果比以往只能靠启发式缓解畸变的做法干净得多，实验显示接缝瑕疵被消除，高畸变离群值也明显减少。但它只处理曲线，不涉及整张贴图的生成与补全。

2.5 整块化路线

UniTex [1] 从多视角照片重建贴图，走的是与本文相反的一条路：它重新参数化网格，把原本碎裂的 UV 整理成整块（single-chart），从根上消灭接缝。

它的另一项工作是把光照与材质解耦——通过物理可微渲染，把拍摄时光照的影响从贴图里剥离出来，只留下材质本身。这一点对本文有直接参考价值，因为本文所处理的 AI 生成概念图同样自带光照。

本文不采用这条路线，原因见 1.3 节的约束 C1：重新参数化需要改动既定 UV，而游戏模型的 UV 牵连着法线烘焙、LOD 与平台规范，代价不可接受。

2.6 共同点与本文的位置

把上述四项工作放在一起看，有一个共同点值得注意：[2][3][4] 不约而同地采用了同一类手段——沿表面度量的距离，或与之等价的表面感知位置编码，用以重建跨 UV 的真实邻接关系。这印证了 1.2 节的论断，也表明该方向已有可借鉴的基础，无需从零发明。

然而三者均以生成视觉上美观的纹理为目标，无人以把既有设计稿精确转译为符合生产规范的资产为目标。目标差异所导致的方案差异，正是本文的位置所在。下表汇总四者与本文的关系。

3 中间层设计

3.1 输入输出契约

输入包括：一组多视图二维设计稿（以正交视图为主）待补　视图数量与具体视角尚待明确，是否附带相机参数亦待明确；目标三维网格及其既定 UV 布局；可选的结构化设计意图描述，由大语言模型自自然语言需求产出。

输出为满足 C1 至 C6 的贴图集合，并保留可编辑的中间产物。

此处须强调一点：正交视图并不能覆盖物体的全部表面。对凸形物体，三个方向确实足够；但游戏模型多为凹形，一旦出现凹陷与自遮挡，就会留下任何视图都触及不到的缺口。这不是分辨率问题，也不是拍摄角度问题，而是几何本身决定的。

3.2 三个子问题

  1. 对应：设计稿上的图案元素落在 UV 的哪一位置。属几何问题，工具相对成熟。
  2. 延续：多视图未覆盖的表面，图案应如何延伸。属推演问题，尚无成熟解，是本文认定的真正难点。
  3. 合规：结果是否满足尺寸、通道、接缝与可编辑性要求。

三者之中，延续决定成败，对应决定精度，合规决定能否交付。

3.3 设计空间

以下三条路线按是否绕经三维空间区分。假设　路线 A 精度高而覆盖率低，路线 B 覆盖率高而可控性弱。

路线 A：投影锚定加测地补全

先以投影确定设计稿与表面的对应，再利用沿表面度量的距离，把图案自已覆盖区域向未覆盖区域推演，接缝处按图块边界精确切分（参考 [3]）。

  • 优势：可解释、可回改、接缝处理精确；
  • 劣势：严重依赖视图覆盖，大面积未覆盖区域的推演质量存疑。

路线 B：UV 空间直接生成

以设计稿为条件，直接在 UV 空间生成贴图，并以表面感知编码告知模型每一 UV 位置背后的表面信息（参考 [4]）。

  • 优势：天然覆盖全部表面，不存在未覆盖问题；
  • 劣势：可控性弱，生成结果难以逐个元素回改，与 C4 冲突的风险高。

路线 C：混合，即投影锚定加 UV 空间补全

以投影结果作为硬锚点约束 UV 空间的生成过程，使已覆盖区域忠于设计稿、未覆盖区域由模型推演，且推演结果受表面邻接关系约束。

  • 优势：兼顾精度与覆盖率，锚点保证了可回改性；
  • 劣势：两套机制的接口与权重分配，是本路线实际上的难点。

3.4 推荐路线

假设　路线 C 最契合 C1 至 C6。理由在于可编辑性（C4）在 A 与 B 之间存在直接冲突：A 可改但覆盖不全，B 全覆盖但难改，C 是唯一有可能同时满足两者的结构。

该假设尚未验证。若验证失败，预期退化路径为：优先保住可编辑性，退回路线 A，并将未覆盖区域的处理降格为半自动，即引入人工介入。

3.5 接缝的表示：从硬切分到权重场

路线 C 中尚有一个必须单独决定的问题：接缝应当如何表示。

现有做法以硬切分为主 [3]，即把接缝视为硬边界，在图块边界处精确切开。其优点是边界精确，缺点则是非此即彼：要么对齐，要么切断，不存在中间态。

另一种表示是权重场，即为每一 UV 位置赋予一个连续值，用以表示其靠近接缝的程度，或跨接缝的连接应当有多强。连续量有两点直接优势。其一，它可进入损失函数，亦可作为条件注入生成模型，而硬约束难以优化。其二，它允许对不同接缝区别对待，而非一视同仁。

权重还有第二个来源需要考虑。假设　除几何距离之外，权重还应纳入视觉显著性，即该处在游戏中究竟有多容易被看到。

理由在于，游戏资产的质量要求是"玩家看得到的地方不出错"，而非整张贴图平均美观。载具的顶面与正面玩家时时在看，底面与结构内侧几乎无人过问。把这两者一视同仁，等于把算力平均撒在一整张贴图上。

两处待决

其一，权重化会削弱硬切分所保证的边界精确性，结果究竟是更不易察觉还是变得更糊，须实测方能判断，不得想当然。其二，视觉显著性如何量化目前尚无定论：是屏幕空间占比、法向朝向，抑或由美术手工标定，须先行确定，否则本小节思路无法落地。

另需警惕一种退化：若权重最终只被用于令贴图更平滑，则重蹈 [1] 中以全变分损失冒充质量指标的覆辙。

这一拆分有一层实际意义：即便第 5 步始终做不好，前四步加第六步也已经构成一套可用的辅助工具——它能自动完成投影、自动标出哪些地方没设计信息、自动检查接缝与规范，剩下的由人补。这比现在的纯手流程已经前进一大截。

4 可行性分层与实现分工

第 3 章给出了中间层的设计空间，但并未回答一个更现实的问题：这些环节中，哪些现在就能做成工具，哪些应当交给生成模型，哪些目前还没有把握。本章处理该问题。区分的依据不是技术难度，而是该环节是否存在唯一正确的答案。

4.1 分配原则

原则

能算的不要猜，猜的部分才算不出来。凡存在唯一正确解的几何量，必须由确定性算法给出，不得交由生成模型近似；生成模型只在信息确实缺失、必须推演的环节介入。

理由有二。其一，几何量的误差会累积且难以察觉：贴图偏移若干像素、接缝错开一小段，在成品上往往要到特定视角才暴露，届时返工成本已高。其二，生成模型的输出缺乏可验证性，一旦用于几何计算，错误无法被自动检出。反之，在未覆盖区域根本不存在可供计算的输入，此时推演是唯一出路，也正是生成模型应当介入的地方。

观察

表中六项已验证环节里，四项属工具、三项属人工智能，且均已在日常生产中实际使用。真正构成研究风险的，集中在最后三行：跨接缝一致性、大规模精确对应、可编辑性保持。这三行也正是本课题与既有研究的分界。

4.3 落地路径

建议分三阶段推进，其顺序按风险由低到高排列。

  1. 阶段零，工具化。把表中"工具"一列做成批处理工具，替代手工重复劳动。建议优先　此阶段即使后续研究失败也具有独立价值，因为它解决的是确定性的、本来就该自动化的部分，不依赖任何未验证假设。
  2. 阶段一，半自动推演。接入未覆盖区域的推演，但先只做"自动标注未覆盖区域 + 人工兜底"，不追求全自动。此阶段的目标是摸清推演质量的实际分布，而非交付成品。
  3. 阶段二，取消兜底。仅当推演结果能自动通过接缝一致性检查时，才移除人工环节。

这一顺序的意义在于：把"研究风险"与"工程收益"解耦。阶段零立刻产生收益，阶段一与阶段二的成败不影响阶段零。

4.4 判断准则

后续每出现一个新环节，可用以下两个问题决定其归属。

  1. 该环节的输出是否存在唯一正确答案？存在，则交确定性算法；不存在，即信息缺失而必须创造，则交生成模型。
  2. 若出错，能否被自动检出？能，则可以放心交给生成模型，因为错误会被拦下；不能，则必须保留人工介入，或为其补一个可校验的约束。

第二问尤其重要：生成模型能否被使用，往往不取决于它有多准，而取决于它的错误是否可被发现。这也是本文坚持把几何量交给确定性算法的根本原因。

5 验证方案

状态声明

本节为方案设计，尚未产生任何实验数据。凡"实验表明"式的表述均不得出现在后续版本中，除非本节已被实际执行。

5.1 待验证假设

  • H1：跨接缝的图案断裂可被量化，且几何约束能显著降低该指标（对应 RQ1 与 C5）；
  • H2：未覆盖区域的推演结果，在人工评判下达到可接受比例（对应 RQ2 与 C6）待补　需定义"可接受"的判定标准与评判人数；
  • H3：全流程可在无人逐面介入的条件下完成（对应 RQ3 与 C2）。

5.2 数据

待补　需确定模型数量与复杂度梯度，是否包含高亏格、薄壁、自遮挡严重的样本；设计稿来源为人工绘制抑或生成；是否设置真值参照。

5.3 评价指标

表 5　拟采用的评价指标

指标说明备注
接缝连续性跨接缝处的颜色与结构跳变程度，越低越好本文主指标
设计保真度结果与设计稿的感知相似度须与上一项权衡，并非越高越好
覆盖率无空洞、无噪点的表面占比—
人工可接受率从业者盲评的通过比例需预设评判规则

一条必须遵守的纪律

不得以"平滑度"类指标冒充质量指标。已有前例 [1]：该方法以全变分损失作为纹理质量的代理指标，而其自身数据即显示，平滑度达到最优时渲染质量反而下降。本文的接缝连续性指标必须直接测量接缝处的跳变，而非整体平滑程度。

5.4 对照与消融

待补　需设置三类基线：无几何约束的基线、仅投影无补全的基线、仅生成无锚点的基线。消融项至少包含表面邻接约束的开关与锚点权重的取值。

5.5 预设失败条件

为避免事后找补，在此先行写定：若 H1 在预设数据上未达成，或 H2 的人工可接受率低于预设阈值，则判定路线 C 不成立，退回路线 A。阈值 待补。

6 风险与局限

  • 最可能失死的环节假设　延续，即 3.2 节子问题二。它属推演问题而非几何问题，且缺乏真值参照。
  • 指标风险：接缝连续性如何度量才不至于退化成平滑度，目前尚无定论。
  • 规模风险待补　数十万面量级下，沿表面度量的计算开销是否可接受，本文未做估算。
  • 样本偏差：现有判断来自单一从业者的实践，未经交叉验证。
  • 披露风险：若后续考虑专利申请，公开技术细节之前应先完成申请。

7 下一步

  2. 补齐 3.1 节输入契约的细节，明确视图数量以及是否附带相机参数；

  4. 确定最小可行验证的规模，建议先取单一模型、单一设计稿，跑通端到端，再论指标；
  5. 执行第 5 节方案，或先执行其中的最小子集。
